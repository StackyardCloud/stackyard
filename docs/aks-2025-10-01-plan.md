# Azure AKS (`aks-2025-10-01`) Staged Plan

## Objective

Emulate Azure Kubernetes Service (AKS) management-plane APIs (`2025-10-01`) with deterministic local behavior for cluster lifecycle, node pools, maintenance, private networking, snapshots, managed namespaces, and trusted access workflows.

## Non-Goals

- Do not change AWS behavior.
- Do not change GCP behavior.
- Do not require live Azure resources for local examples.
- Do not emulate full Kubernetes control-plane or node runtime internals in this phase.

## Route Envelope

Stackyard route envelope for this service:
- `/azure/providers/Microsoft.ContainerService/operations`
- `/azure/subscriptions/{subscriptionId}/providers/Microsoft.ContainerService/*`
- `/azure/subscriptions/{subscriptionId}/resourceGroups/{resourceGroupName}/providers/Microsoft.ContainerService/*`

Target API version:
- `api-version=2025-10-01`

## API Surface and Contract Notes

Operation groups reviewed:
- 12 operation-group pages.

Method pages reviewed:
- 65 method pages linked from those operation groups.
- Coverage includes operation-level details for all methods in `agent-pools`, `machines`, `maintenance-configurations`, `managed-clusters`, `managed-namespaces`, `operations`, `private-endpoint-connections`, `private-link-resources`, `resolve-private-link-service-id`, `snapshots`, `trusted-access-role-bindings`, and `trusted-access-roles`.

Common contract characteristics from method pages:
- Management-plane ARM resource patterns under `providers/Microsoft.ContainerService`.
- Success status families include `200`, `201`, `202`, and `204` depending on operation semantics.
- Non-success responses use typed `ErrorResponse` payloads (`Other Status Codes`).
- API includes synchronous reads/lists plus long-running create/update/delete/action operations.

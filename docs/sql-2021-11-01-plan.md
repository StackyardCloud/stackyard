## Behavior

CRUD, listing, cascade and error behavior come from the shared ARM handler (see `docs/resources-2021-04-01-plan.md`). Service-specific rules:

- server names are 1-63 lowercase letters, digits or hyphens and cannot start or end with a hyphen; database names are at most 128 characters, cannot contain `<>*%&:\/?` and cannot end with a period or space (400 `InvalidResourceName`)
- servers need `administratorLogin` and `administratorLoginPassword` unless `administrators.azureADOnlyAuthentication` is true; reserved logins such as `sa`, `admin` or `dbo` are rejected; `minimalTlsVersion` must be `1.0`, `1.1`, `1.2`, `1.3` or `None`
- `administratorLoginPassword` is accepted on PUT and PATCH but never stored or returned
- `fullyQualifiedDomainName` (`{name}.database.windows.net`), `state` and the default `version` `12.0` are server-owned
- every server has a `master` database in its region with the `System` SKU
- databases and elastic pools are tracked resources and need a `location`; databases report `status` `Online`, a stable `databaseId`, a service objective that follows `sku.name` (default `GP_Gen5_2`) and the default collation `SQL_Latin1_General_CP1_CI_AS`
- firewall rules need IPv4 `startIpAddress` and `endIpAddress` with start not greater than end; `0.0.0.0` to `0.0.0.0` is the usual allow-Azure-services rule
- `checkNameAvailability` compares names across all subscriptions, because host names are global

Out of scope for this stage:
- the TDS protocol (no database engine runs)
- Microsoft Entra administrators as a child resource, auditing, threat protection, failover groups, geo-replication, backups, restores and copies
- checks that a database's location matches its server's, or that `elasticPoolId` names an existing pool
